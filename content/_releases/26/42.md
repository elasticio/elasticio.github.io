## New Features
### Transfer Flow Designer page functionality to React (Graph Builder)
The Flow Designer, where you build and manage your integration flows, has been migrated from Ember.js to React. This significantly modernizes the Flow Designer's underlying technology and provides a modern foundation for maintaining and extending the flow-building experience.

### Copy and paste a step in the flow
The Flow Designer now supports copying and pasting action steps, making it easier to build and extend integration flows without configuring similar steps from scratch.

Each action step in the flow graph has a **Copy** button to the left of its component. Clicking this button copies the step's configuration details and saves them to the browser's local storage, allowing you to paste the copied step into the flow.

When a step has been copied, a red **Cancel** button appears on the left side of the Designer header. Click **Cancel** to clear the copied step details and discard the pending copy operation.

To reuse a copied step, use the paste functionality in the Designer. A new step is created using the copied configuration, so you can reuse existing settings instead of manually configuring the same component again. After the step is pasted, the copied data is automatically cleared from the buffer.

This functionality helps reduce repetitive configuration work, speeds up flow development, and makes it easier to reuse existing step configurations when building integration workflows.

**Note:** Only action steps can be copied and pasted. To use this functionality your flow must be in Draft mode. The Error Handler step can't be copied.

### Mapping data is always taken from passthrough
Previously, mappings referenced the previous step's body directly. If a new step was inserted between the original step and the mapping step, the mapping could break.

Mapping data is now always taken from passthrough, even when the data originates from the previous step. With this improvement, mappings use passthrough as the data source, helping preserve existing mappings when steps are inserted into a flow.

### Support for OAuth2 Client Credentials flow
Added a new auth type for Auth Clients - `oauth2_client_credentials`. To use it, specify `"authClientTypes": ["oauth2_client_credentials"]` in `component.json`. It can be used together with the `oauth2` type to let users choose which authentication to work with.

Refresh token logic: if the provider does not return the `tokenExpiresIn` field, a default of 1 hour is used, after which the token is refreshed.

Example of `component.json`:
```json
"authClientTypes": [
  "oauth2",
  "oauth2_client_credentials"
]
```

### Credential ID fully visible on the Credentials page
Credential IDs are now fully displayed on the Credentials page, regardless of the credential name length. Previously, IDs could be truncated with three dots when the credential name was too long.

### New `FileTextView` view in the credentials widget
A new `FileTextView` view has been introduced with the following additional parameters:

* `accept` - a comma-separated list of allowed file extensions in the format `.fileExt,.fileExt2`, for example, `.txt,.crt`. Default value: `*`, which allows files with any extension.
* `maxlength` - the maximum allowed file size in MB. Default value: `5`.

Example of the `component.json` credentials object:
```json
"requiredFileField": {
  "viewClass": "FileTextView",
  "accept": ".txt,.crt,.jpg,.png",
  "maxlength": "5",
  "required": true,
  "label": "Required File Field"
}
```

## Fixed Bugs
*   **FIXED** an issue where the execution page hung while loading the graph.
*   **FIXED** an issue where the component mapping was reset when a step was inserted before the component.
*   **FIXED** an issue where Raven ignored the tenant Mandrill configuration and sent emails via the platform SMTP. Raven now correctly detects and uses a tenant-specific `mandrillApiKey` when sending emails, even when the platform-level SMTP adapter is enabled. Tenants without their own Mandrill configuration continue to use the platform SMTP configuration as before.
